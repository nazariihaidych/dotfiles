# Neovim Config Changes — 2026-11-04

Floating-window UI pass: gave the which-key popup, all floating windows, and the
help window a consistent rounded border, and made completion/hover/float
backgrounds transparent (terminal show-through) to match.

## 1. which-key popup border

**File:** `lua/plugins/which-key.lua`

Added a `win.border` to the (previously empty) `opts`:

```lua
opts = {
  win = {
    border = "rounded", -- "none" | "single" | "double" | "rounded" | "solid" | "shadow"
  },
},
```

which-key is **v3.17.0**, where the window key is `win` (v2 used `window`).

## 2. Global border for all floating windows

**File:** `lua/config/options.lua`

```lua
vim.opt.winborder = "rounded"
```

`winborder` is a Neovim **0.11+** global option (running 0.12.6). It sets the
default border for floating windows that don't specify their own — LSP hover,
signature help, diagnostic floats, Lazy/Mason UIs, etc. A few plugins hard-code
their own border and will ignore this.

## 3. Bordered `:help` / `:Man` window

**File:** `lua/config/options.lua`

`:help` normally opens as a **split**, and splits can't have a border — so
`winborder` doesn't affect it. This autocmd converts the help/man window into a
centered floating window, which then shows a border:

```lua
vim.api.nvim_create_autocmd("FileType", {
  group = vim.api.nvim_create_augroup("HelpFloat", { clear = true }),
  pattern = { "help", "man" },
  callback = function(args)
    if not vim.bo[args.buf].buflisted then
      local win = vim.api.nvim_get_current_win()
      local width = math.min(120, math.floor(vim.o.columns * 0.85))
      local height = math.floor(vim.o.lines * 0.85)
      pcall(vim.api.nvim_win_set_config, win, {
        relative = "editor",
        width = width,
        height = height,
        row = math.floor((vim.o.lines - height) / 2),
        col = math.floor((vim.o.columns - width) / 2),
        border = "rounded",
      })
    end
  end,
  desc = "Open help/man in a bordered floating window",
})
```

**Behavior change:** help now **floats, centered at 85% of the screen** instead
of splitting. Adjust `width` / `height` / `row` / `col` to resize or reposition.

## 4. Transparent completion / float backgrounds (theme)

**File:** `lua/plugins/gruvbox-material-theme.lua`

In the theme's `customize` callback, the highlight groups for completion and
hover popups — `Pmenu`, `PmenuExtra`, `PmenuThumb`, `PmenuSbar`, `PmenuKind`,
and `NormalFloat` — had a hard-coded solid background (`colors.bg3`). This made
the bordered floating windows look boxed-in against the transparent editor.

Changed to honor the theme's transparency flag:

```lua
-- was:
opts.bg = colors.bg3

-- now:
opts.link = nil
opts.bg = gruvbox_material_transparent and "NONE" or colors.bg3
```

- When `gruvbox_material_transparent = true` (current setting), these popups get
  **no background** — the terminal shows through, matching the "terminal-like"
  look of the which-key window and the new bordered floats.
- When transparent mode is off, they fall back to the solid `bg3` so they still
  stand out.
- `opts.link = nil` is needed so the explicit `bg` isn't overridden by a linked
  highlight group.

**Revert:** restore the single line `opts.bg = colors.bg3` in that block.

## Changing the border style

All three use `"rounded"`. To switch globally, change the `winborder` value and
the two explicit `border = "rounded"` lines to any of:
`"none" | "single" | "double" | "rounded" | "solid" | "shadow"`.

## Reverting

- **which-key border** — empty the `opts` in `which-key.lua`.
- **Global border** — remove the `vim.opt.winborder` line.
- **Floating help** — delete the `HelpFloat` autocmd block; `:help` returns to a split.
